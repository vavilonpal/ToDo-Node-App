### Шаг 5. Реализация выбранного варианта
### WebSocket
**Идея**: Реальное-время обновления списка задач / категорий / уведомлений<br>
WebSocket-функциональность: “Live Updates”<br>
**Когда**:
- создаётся задача
- обновляется задача
- удаляется задача
> REST обрабатывает запросы → WebSocket уведомляет всех клиентов.

клиентам автоматически отправляются обновления в реальном времени.
1. Добавьте необходимые зависимости
```shell
 npm install socket.io jsonwebtoken
```
2. Создаем  WebSocket сервер (utils/socket.js)
```js
const jwt = require("jsonwebtoken");
const logger = require("./logger");

module.exports = (io) => {

   io.use((socket, next) => {
      const token = socket.handshake.auth?.token;

      if (!token) {
         return next(new Error("NO_TOKEN"));
      }

      try {
         const payload = jwt.verify(token, process.env.JWT_SECRET);
         socket.user = payload; // { id, email, role }
         next();
      } catch (err) {
         next(new Error("INVALID_TOKEN"));
      }
   });

   io.on("connection", (socket) => {
      logger.info(`🔌 WebSocket подключён: ${socket.user.email}`);

      socket.emit("connected", {
         message: `Добро пожаловать, ${socket.user.email}!`
      });

      socket.on("disconnect", () => {
         logger.info(` WebSocket отключён: ${socket.user.email}`);
      });
   });
};

```
Подключаем WebSocket к серверу:
```js
const { Server } = require('socket.io');

const io = new Server(server, {
   cors: { origin: "*" }
});

// Подключаем логику WebSocket
require('./utils/socket')(io);
socketClient.setIo(io);
module.exports = { io };

```
Пример использования WebSocket в контроллере:
```js
exports.deleteTodo = async (req, res) => {
   try {
      const todo = await Todo.findByPk(req.params.id);
      if (!todo) return res.status(404).json({ message: 'Todo not found' });

      await todo.destroy();

      io.emit("task.deleted", todo);

      res.status(204).send();
   } catch (err) {
      res.status(500).json({ message: err.message });
   }
};
```


## Контрольные вопросы

1. В чём основные отличия REST от выбранного вами типа Web-API (WebSockets)
- REST — статичный, работает по принципу запрос–ответ.
- WebSocket — постоянное двустороннее соединение между клиентом и сервером.
- REST отправляет данные только по запросу, WebSocket — по событию в реальном времени.
- REST использует HTTP, WebSockets — отдельный протокол ws:// или wss://
2. В каких случаях использование вашего типа API даёт преимущество по сравнению с REST (по производительности, удобству, гибкости и т.д.)?
WebSocket лучше, когда нужно:
- передавать данные в реальном времени;
- избегать постоянных REST-запросов для обновления данных;
- снизить нагрузку на сервер при динамичных данных.
3. Какие ограничения или недостатки имеет выбранный вами архитектурный стиль?
- Сложнее масштабировать (нужен Redis adapter или аналог).
- Постоянное соединение → выше нагрузка на сервер.
- Требует аккуратного управления подключениями.
- Не подходит для простых CRUD-операций, где REST проще и дешевле.
4. Как вы интегрировали новый тип API с уже существующей архитектурой приложения (REST + БД + аутентификация)?
- Сервер WebSocket поднят на том же HTTP-сервере, что и Express.
- Для аутентификации используется тот же JWT, что и в REST.
- События WebSocket вызываются из REST-контроллеров после создания/обновления данных в БД.
- БД (Sequelize) остаётся основной — WebSocket лишь уведомляет клиентов о событиях.
- REST продолжает работать как обычно, а WebSocket добавляет live-обновления.
